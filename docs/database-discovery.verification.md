## 连接、取证与权限

通过同一个已授权 MySQL 资源可自主选择多个相关库，不需要逐库逐表登记或使用专用只读账号。项目可继续明确固定库，配置撤权仍会使旧资源身份失效。没有环境标记的库名须用数据源归属和任务范围核对。数据库连接、读事务、业务写入和恢复分别遵循现有权限。

SQL 观测保存实际连接库、身份匹配、采集时点和驱动提供的列来源。计划中的数据库、表和对象仍须与实际观测对齐。未新增 SQL 全量解析、行级审计或数据库协议。选库检查约束连接目标；SQL 中其他对象的可见权限由数据库服务端及已核实的操作合同决定。

## 真实 LTX SIT 只读结果

- 已在实际 MySQL 5.7 服务器上核验无默认库连接与当前主体匹配。库存服务 SIT 源码的数据源与现有主库连接一致。可选中 `ltx_inventory_sit` 并读取 `ltx_customer_inventory` 的实际结构。按同一主键和租户复核一条未删除记录，留存去标识结果及实际列来源。首次读回用了普通等号对比空租户，返回零行；用 MySQL 空值安全比较重查返回一行。该差异属于核验语句修正。
- 浏览器真实打开 `/login`，HTTP 200，实际出现登录输入框。网关转发的认证健康接口返回 HTTP 503，报告 `DOWN`；构建信息入口返回 HTTP 401。未取得实际构建及生效日志脱敏证据，真实凭据未提交，登录身份、角色及登录后页面、业务 API 与同一对象整链保留阻断。
- 候选实例配置已用真实连接验证主库和库存资源，正式运行配置、共享 INI 及专员进程未改。本轮真实业务写入和生产连接均为零。真实 SIT 独立报告保留数据库及未登录页面通过、认证整链阻断的结论。
