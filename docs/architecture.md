# AgentOS 架构与仓库设计

1.52.1源码准备的逐仓进度、安全诊断、远端读取重试与分支竞态固定提交处理见[源码同步](source-sync.spec.md)。所有配置仓的完整性与环境隔离保持。

1.52.0长任务与查询规则见[完整查询与大结果接续](long-query-continuity.md)：原范围自动复核续期、无整批查询截止、历史数据不按24小时失效、大结果保存续读；不改变只读权限及完整文件核验。

报表数据层共用SQL/Mongo的声明式期间统计与数据集恢复，规划器携带当前草稿和未修正核验缺口；完整对象期间展开、累计去重及分页展示见[报表效率与接续](report-efficiency.md)。不改变消息路由、执行授权或任务完成门控。

## 目标

AgentOS 把飞书群里的五种团队身份连接到一台可信开发机上的 Codex。它负责消息接入、角色路由、任务状态、人工门、隔离工作区和结果卡片，不替代 Git、业务 CI、部署平台或真人最终责任。

## 三条主链路

```mermaid
flowchart LR
  U[群成员] --> F[飞书机器人]
  F --> E[lark-cli 长连接]
  E --> C[Control Plane]
  C --> S[(data/agentos.json)]
  C --> A[只读 Codex app-server]
  C --> Q[Job 队列]
  R[Bounded Runner Pool] --> Q
  R --> W[data/worktrees]
  W --> X[Codex exec]
  X --> B[业务仓库变更与验证]
  C --> F
```

1. 普通对话：飞书消息 → 对应 profile → Control Plane → 常驻只读 Codex app-server → 回复或结构化动作建议。
2. 研发任务：Control Plane 创建 Job → Runner 领取租约 → 隔离 Git worktree → 独立 `codex exec` → 验证 → 卡片结果 → 真人放行下一阶段。
3. 卡片动作：`card.action.trigger` → 身份、群、消息、版本、状态和权限校验 → 原卡更新；按钮本身不调用 AI。

## 角色与交接

| 角色 | 主要责任 | 默认下一站 |
|---|---|---|
| 项目负责人 `owner_intake` | 理解目标、范围、风险、验收；必要时追问 | PM 或只读分析 |
| PM `pm` | PRD、Spec、边界、异常、权限、可测试验收 | 开发 |
| 开发 `developer` | 实现、构建、自测和真实工件交接 | 测试 |
| 测试 `qa` | 独立验证正常、异常、边界和回归 | 审计或退回 |
| 审计 `owner_audit` | 审查需求、差异、证据、安全和残余风险 | 项目负责人汇报 |
| 项目负责人 `owner_report` | 汇总最终结论；复用负责人机器人 | 真人验收 |

角色提示词在 `config/roles/*.md`；程序强制状态、权限和工件规则在 `src/`。提示词不是操作系统沙箱，也不能代替真人审批。

## 仓库结构

```text
agentos/
├─ config/                 脱敏示例、角色规则、协议 schema
├─ docs/                   架构、部署、数据地图和功能规范
├─ scripts/                初始化、诊断、启动、自启和烟测
├─ src/
│  ├─ control-plane/       飞书接入、对话、任务、卡片、管理页面和 HTTP
│  │  └─ admin/            本机管理控制台静态页面
│  ├─ runner/              租约、工作树、Codex 执行和验证
│  └─ shared/              状态、协议、Codex app-server/runtime
├─ test/                   Node 内置测试运行器的完整回归
├─ test-support/           测试夹具
├─ data/                   本机运行态，Git 忽略
├─ README.md               产品入口
└─ SECURITY.md             发布和运行安全边界
```

## 状态和一致性

- `JsonStore` 把状态写入临时文件后原子重命名为 `data/agentos.json`，并在单进程内串行事务。
- 同一个控制面在 `/admin` 提供本机管理页面，并在 `/api/v1/admin/*` 提供脱敏记录与模型设置接口。页面先建立本机同源会话；写配置还要通过 Origin 和专用请求头检查。非回环监听时管理页面关闭。
- 飞书消息用 source message ID 去重；卡片动作还有事件、消息、角色、群、状态和 action version 校验。
- 单一控制面管理有界 Runner 池，默认 3 个执行槽；每个槽用独立 runnerId 和租约领取不同 Job，同一 Job 仍只能被一个槽执行。取消必须等待实际任务进程树退出。
- 卡片投递失败只重试投递，不重新运行 Codex；未送达动作先保存在 `pending-card-actions/`。
- 单机 JSON 是当前产品边界。不要让两套 Control Plane 同时写同一个数据文件；多机高可用需要另行设计存储和分布式锁。
- 新分析链是一个持久 Job：开发 Codex thread 提出受控环境请求，Runner 在当前租约内执行数据库或网页只读工具，把证据写回同一 Job，再恢复原 thread 继续判断。内部步骤不重新排队、不生成后继开发 Job，也没有额外负责人汇总模型轮次。相同且已拒绝的查询连续出现时才以证据化受阻结束，不设置整项任务的固定总时长或工具次数上限。
- Runner 池默认 3 个槽，多个问题卡可真实并行；同一卡始终单线推进。共享 Chrome 复用同一用户登录态，但每个问题绑定自己的标签页，底层 Apple Events 原子操作串行化，避免不同任务互相导航。等待登录会释放 Runner 槽，登录恢复后由任一空闲槽继续原 Job 和原 Codex thread。

## 工作区边界

- 实施任务：每个 Mission 首次进入开发时在 `data/worktrees/` 创建 `codex/agentos-<job>-<stage>` 分支工作树；后续 QA/审计复用真实工作区和未提交改动。
- 只读分析：Runner 按 analysisRepositories 对各独立仓先做 origin 快进同步，失败即阻塞；再读取 repoPath，使用只读审批策略且不执行业务验证命令。版本证据留在 result.sourceSync，详见 source-sync.spec.md。
- AgentOS 不自动 merge、push 或 deploy。业务代码是否提交由团队现有 Git 规则和真人决定。

## 部署边界

当前成品基线是 Windows 单机 + 当前用户登录后自启 + lark-cli 长连接，无需公网域名。源码保留 HTTPS Control Plane 与拆分 Runner 入口，但公网化、跨机凭据、反向代理、TLS、高可用数据库和严格多租户隔离不属于开箱即用范围。

完整落盘位置见 `docs/storage-and-data.md`；从零部署见 `docs/getting-started.md`。


## 可追溯记忆与台账入口

默认启用近期预算、持久摘录摘要和范围内历史检索；`config/memory.local.json` 可配置，`data/memory.json` 私有保存。分析任务可用项目 `knowledgePaths` 提供台账入口，仍先同步再只读核实，不写台账或扩大权限。详细方案、字段、执行路径、失败恢复与平台限制见 [记忆管理](memory-management.md)。


## 群共享会话与问题主卡片（可选）

在 `config/conversation.local.json` 开启 `groupSessions` 与 `questionCards`，使用 Codex 原生持久会话，并让每个新问题维护一张主卡片。不开启时保留现有隔离记忆和卡片行为；不会改变普通成员权限或改建话题群。配置、使用、状态结构、备份及限制见[群共享会话与一问一卡](group-question-cards.md)。

## 可选环境查询边界

详见[受控环境查询](environment-access.md)和[只读排查自动授权](read-only-auto-authorization.md)。环境配置仅存在 ignored 的 `config/environments.local.json`，凭据保存在当前 Mac 用户 Keychain。经过环境目录、模板、参数和工具边界校验的 UAT/PRD 只读查询自动执行；修改代码、数据、配置、部署或业务状态仍需管理员审批。普通 analysis 沙箱保持只读，查询结果归属原问题卡片且不注入共享长期记忆；真实环境验收须在本机配置后完成。

## 环境工具排查升级

所有成员均可按现有受控策略发起只读排查；新增入口与业务写入仍核验负责人权限。新增 Codex 按范围选择 Nacos API、独立浏览器列表/搜索/详情及 MySQL 结构化查询工具，本机向导可弹出 Nacos 登录窗口，自动发现命名空间并验证连接。固定模板继续兼容。首次凭据仍本机录入，Nacos 业务账号不复用为数据库登录。见 [环境工具说明](environment-access.md)。

浏览器依赖与完整测试：`npm ci` 后运行 `npx playwright install chromium`，再运行 `npm run check`。Linux 使用 `npx playwright install --with-deps chromium` 安装系统依赖。仅启用 Nacos 已适配的只读网页能力；未知网站需另行适配。

## 查询结果交付

环境查询完成后的主卡片直接展示实际结果。数据库端点首屏使用主机/IP、端口、库名，重复读取的同一端点去重；超过两项的结果在详情保留。没有记录明确说明未返回，部分结果保留未完成标记。密码、token和账号字段不进入展示。卡片首屏不再以“已查询若干条”替代答案；授权参数移至结果详情，等待批准时仍完整显示本次范围。群共享记忆继续使用不含端点的过程摘要，实际结果保留在本次任务与卡片中。既有历史结果不重写、不自动重发，新任务使用新展示；流程架构未变。

## 群内引导接入与完成卡片保留

环境接入采用持久申请→管理员确认→Mac本机登录与范围选择→恢复原提问人查询的流程，详见 environment-access.md。接入与生产查询审批分离，只有实际窗口/保存状态才触发进度。进行中的问题复用卡片；完成后的追问新建关联问题卡，保留旧答案。没有新增消息消费者或后台定时任务；轮询由现有控制面调度负责。

## 环境源码快照

可选 `analysisSourceMode=isolated`：以配置的项目根目录为来源，根据问题选择 `analysisEnvironments`，在 `analysisSnapshotRoot` 下创建独立同步快照。保留个人功能分支与未提交修改；环境未指定且无默认值时先询问，禁止回退 PRD。上文原目录快进同步规则仅适用于未启用此选项的兼容模式。同一卡内的源码与工具步骤复用同一分支/提交证据，仍不能证明实际部署版本。配置、清理与验收见 [源码同步说明](source-sync.spec.md)。

## 按问题发现业务网站

支持从问题与环境源码查找入口；Mac 默认接管日常 Chrome 的已登录页面，其他平台或显式配置可使用独立浏览器。等待网站登录时保留任务、卡片写明具体入口，网站负责人可直接回复该任务卡提交自然格式的账号密码；凭据写入 Mac Keychain，由固定程序完成登录，模型与任务状态不接触凭据，登录后自动恢复。`BROWSER_BRIDGE` 表示后台进程缺少 macOS Chrome 自动化权限或原生桥接暂时无法取得 Chrome 对象，与网站登录状态分开处理，任务保持等待并在桥接恢复后自动继续。连续调查若在更早轮次已经形成通过交接校验的源码或数据库结论，末端补充环境读取失败时保留这些结论与原始错误环节，未完成需求保持受阻；不能用无效部分结果掩盖原故障。配置、权限、存储与兼容边界见[通用网页排查](query-driven-websites.md)和[日常 Chrome 复用](shared-chrome.md)。

## 可选团队知识层

知识层独立于个人记忆与任务状态。已完成且验证通过的通用analysis异步提炼进入SQLite，按明确项目/群/profile/成员范围检索，原对话Codex做语义判定，程序核对版本、依赖、有效期再复用规范答案。纠错/冲突暂停复用；权限、实时数据与执行动作沿用原链路。配置、存储、部署版本边界与个人验收要求见[团队知识](team-knowledge.md)。搭建与验收步骤同时纳入完整部署提示词；文档说明不代替目标团队真实业务验收。

## 可选联系人信息图

主对话类型化lookup_contact动作调用本机ContactDirectory，按项目/群/profile/可选提问者配置过滤，在机器人通讯录范围内完整分页并匹配；重名先确认，唯一人员进入隔离无头Chromium生成PNG。出站保留原消息和profile，发送前复核范围、可见字段与摘要，发送失败只幂等重试。不会调用桌面自动化或个人账号，详见[配置与验收](contact-images.md)。

私有卡片：显式正文开关→冻结问题收件者→普通群临时卡片替换/清理，话题群明确不兼容则同机器人私聊→附件私聊。公开投递无降级入口；详见[私有卡片](private-cards.md)。

查人专用普通群由`contact-channels.local.json`显式启用：仅查人/补充，不暴露业务任务入口。图片嵌入私有图卡，分别投递给提问者与实时群主，受众变更拒发旧副本；普通业务群行为不变。见[联系人配置](contact-images.md)。

Runner关键交接使用durable-control-v1：同号请求合并，状态变更与回执索引同事务提交，超时后核对原回执并接续；保留租约、取消与未知旧协议拒绝盲重试。状态签名缓存、空闲轮询和心跳合并降低整文件读写压力。配置、存储、失败边界及验收见[本机控制请求恢复](control-recovery.md)。

报表关联区分唯一维度查找与一对多分组：日期保留数据库字符串，显式左关联保留缺失明细，组合行键与独立范围核验防止多月份丢行；实际参数错误有持久去重的定向修复接续，不放宽权限。见[报表粒度与修复接续](report-grain-recovery.md)。

后台高频读取先通过内部选择器提取记录再复制，冷读按实例合并；本机启动器的实际工作进程登记及退出恢复不绕过租约或自动重跑。见[空值与本机异常退出恢复](local-executor-recovery.md)。

固定提交历史由Runner类型化操作后恢复同一只读会话；期间变换、实际文件审阅、发布记录取证及缓存维护边界见[多系统通用能力](multi-system-capability-audit.md)。


## 公开话题追问的环境与操作权限（1.52.2）

同一群、机器人profile、项目及明确回复/话题关联中的公开问题，可由另一成员引用其历史背景。attachQuestion仍创建属于当前成员的新问题和新卡；只有原发起人或可信管理员才能复用原活动任务。私有结果、通讯录专用通道、其它群/项目/profile不因同一个root_id开放。

questionSourceContext沿经边界核验的问题父链取得已登记的源码环境ID；buildInput提供环境与历史源码定位信息，create_task在本轮没有另选环境时用它补齐sourceEnvironment。当前用户明确选择其它已登记环境时新建对应环境调查，不更改旧任务的固定提交。新无关话题仍需独立选择，不能取群里最新任务的环境。环境上下文不含原租约、凭据或查询授权，planQuery和原任务控制权限照常核验。

continuous_analysis的固定快照在sourceRoot匹配时可作为历史定位线索保留答案；requiresRecheckForCurrentSource仍为true，不能把它作为当前源码/部署事实。源码字段和结构说明可直接以文字或Markdown表格交付；用户未要求文件或完整线上普查时不自动增加CSV、validator等完成门。明确要求文件及业务统计报表的完整性和文件核验保持。规则在config/conversation.md、conversation.schema.json和roles/analysis.md同步，提示词仍不是环境权限。

部署无需新增通用配置或依赖，更新主控/Runner后按空闲维护流程重启。已有错误关联历史不会自动重写，需要维护者针对原问题核对修复；不批量重放群消息。迁移代码包包含上述文件，实际生产元数据、群交付、平台/跨机验收另由部署实例保存。

TCT调度作为独立environment kind，使用已审核HTTPS入口、租户/地域及精确分组范围。环境授权每次HTTP读取复核；模型只见固定只读工具和脱敏元数据，任务ID保持精确字符串。会话按连接凭据在进程内共享，过期只重试固定读取，不能盲目重放登录或执行调度。详见[tct-readonly.md](tct-readonly.md)。

源码调查的同名入口核验：旧版/迁移版和当前页面需通过实际菜单或已授权运行入口区分；调度频率需关联处理类、调用链和目标写入表，不能凭相似任务名称套用。该行为由analysis角色约束引导，仍须用真实证据验收，不是程序自动证明每条业务映射。

1.54.0新增显式业务口径版本库，按配置团队共享，独立于个人记忆和有TTL的源码知识。定义带用户确认来源，传入对话、源码和环境调查；源码按依赖路径分层并行，环境batch_read减少独立小步骤的模型往返，保留逐项门控和错误证据。配置与边界见team-knowledge.md、report-efficiency.md。
