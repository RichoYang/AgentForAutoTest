# 执行前契约、分类与页面阶段

适用版本1.52.0，问题及关闭条件见[范围](execution-preflight.spec.md)，实际结果及归属见[验证记录](execution-preflight.verification.md)。沿用1.51.0 Windows锁、恢复和私有DACL，沿用测量基线、独立预期、精确数值、nullAs/evidenceRefs、变更台账与固定15表报告，不把历史模型结果当本次结果。

## 计划与测量

`test_plan`仍按原预期行覆盖`checks`和`processChecks`。程序提供逐行`coverageMatrix`，包括原文、业务检查、过程检查和关联ID，核验ID/引用/覆盖及完全重复的契约；不同字段、渠道或条件的合法拆分保留。独立模型结合原需求和完整原用例判断角色。产品删除后不可检索可能是业务目标；测试结束删除自己准备的数据是过程。不能只看“删除、清理、恢复”等关键词，也不能将混合原句整个归为一种角色。

内嵌`measurement`在发布冻结计划前完成核验。若身份、渠道或测量审查失败，原始候选与字段错误留档，候选尚未冻结，可修正后再次提交；已经冻结的业务预期仍不可随结果改变。没有提供测量方法的检查仍须在场景写入前完成`test_measure`，独立审查会检查是否具备执行所需方法。

空集合不提供`rows[0]`身份。`test_snapshot`的`contract.scope`来自实际范围采集及完整性校验，可以结合源码/schema证明空集合范围；任意输入参数和模型声明不具有同等证明力。未来子记录尚不存在时，可以用真实父对象、已证明的范围和DTO/schema预检未来路径，不要求提前制造场景结果。真正断言仍须本时期的新业务观测。

## 返回类型与准备写入

数据库只读结果保留原始`rows`、`count`，附加实际协议列元数据`columns`。每项包含`name`、`columnType`、`flags`、`characterSet`及连接器固定编码能够证明的`representation`；JSON、二进制或未知类型不猜标量编码。在当前mysql2精确数值配置下，BIGINT、DECIMAL及日期按文本保留；类型元数据不是业务结果。

完整回读的恢复摘要排除由连接器生成的列类型元数据，业务行、计数和其他原始字段仍完整比较，显式stateFields保持精确选择。这样旧版没有columns的恢复快照仍可回查；不是忽略业务变化，也不修改旧原始证据。列/schema变化仍由操作边界和查询校验核验。

准备/场景写入前，根据实际查询列和已证明的固定编码核验后态字段及`expected`类型。空结果仍有查询列信息，故可拒绝拼错字段或将DECIMAL预期写成JS number，同时允许未来新增的合法行。API的动态响应类型由已有原始回读及实际构造源码审查，不机械要求所有未来字段都在当前样本中存在。

数值检查仍按精确`decimal-text`比较。程序传递编码证明，不要求把数字字符串转成可能丢精度的JS number，也不只为类型差异额外拼计算。null、missing、空字符串、错误响应分别保留；只有经源码审核的显式`nullAs`转换有效，不能默认补零。

## 页面阶段

普通单次页面断言保持原接口；需要区分首次、切换和切回等时序职责时，在计划中声明有序`pageStages`，检查通过`pageStage`关联。阶段身份来自真实DOM预检，不放进虚构的“阶段”身份字段。

```json
{
  "steps": ["场景后进入A并观察", "切换B并观察", "切回A并观察"],
  "pageStages": [
    {"id":"first-A","step":1,"resource":"platform","action":"goto","path":"/page?key=<本轮A业务键>","subject":{"business_key":"<本轮A业务键>"}},
    {"id":"switch-B","step":2,"resource":"platform","action":"goto","path":"/page?key=<本轮B业务键>","subject":{"business_key":"<本轮B业务键>"}},
    {"id":"return-A","step":3,"resource":"platform","action":"goto","path":"/page?key=<本轮A业务键>","subject":{"business_key":"<本轮A业务键>"}}
  ]
}
```

这是计划局部示例，检查仍须完整的原预期行、独立预期、渠道、subject、basis和measurement；将对应检查设为`pageStage:"first-A"`等，并提供阶段身份维度的测量路径。`step`是steps从1开始的编号，`resource`须已授权。`goto`使用实际相对`path`；`click/select`使用实际`selector`，必要时固定`value`。先按源码核实操作语义，不能据此授权浏览器业务提交。

主机在实际页面动作时生成`lifecycle.pageAction`，包含不可由模型填写的动作ID、类型及开始时点；后续多次观察保留同一动作关联。实际页面动作、就绪后的DOM/截图、资源、epoch及场景开始边界共同决定阶段。预检导航不属于场景；后来再次进入A也不变成历史首次A。每个必要阶段在下一次切换前保存就绪后的`observe`，不等待目标金额或期望内容。

确定性阶段不符在字段语义模型之前拒绝，错误包含要求阶段、实际动作/阶段、缺失阶段、同阶段受影响检查及可复用观测。`test_plan {action:"inspect"}`可读取阶段时间轴、候选观测和缺口，`test_evidence`回读同epoch的正确原始页面观测后可用于其他同阶段字段。字段别名变化只能在实际选择器/read一致时关联身份；不能用其他对象/渠道/时期代证。

执行过程审核也接收同一主机阶段时间轴、动作生命周期以及已比较观测的ID和时点，不要求模型把观测metadata中的at伪装成业务data字段。页面动作顺序证明不替代中间业务动作的因果先后；跨业务步骤仍结合实际变更台账和源码独立核验。

若历史阶段没有正确页面证据，新增导航无法补造过去，应检查已保存原始证据；仍无法证明时走现有恢复、回查和重测。冻结阶段映射和其步骤不能事后改标签。相同阶段缺口按共享目标累计，修辞变化或新增错误阶段观测不解决缺口；沿用已有重复无进展机制，没有新增任务总时长、轮数或调用上限。

共享缺口合并展示总尝试和关联检查，但重复阈值保持原来的每检查目标口径。模型可能在收到第一项反馈前已提交多个兄弟检查；不能把第三个检查的首次错误当成同一检查第三次无进展。重复同一检查仍按原规则判断。辅助证据路径拼错时，错误给出实际根字段和父字段，供回读修正，不自动改路径或补值。

阶段关联只证明取证职责。业务展示值是否正确仍由独立预期和程序比较决定；正确阶段的错误产品值应判失败，不能要求先修产品或用API代替页面。

## 运维及验证边界

无需迁移现有配置或旧Windows v1登记。本轮不部署、不重启、不改专员权限、不发真实群消息；原取消任务只读。验证使用新的专用回环服务、MySQL及Chromium，真实模型保持实际配置。历史候选重放、固定模型和协议夹具只算模块证据；库存与冻结后留出另走正常需求Runner、自主模型和真实工具，模拟飞书传输不算真实群入口。
