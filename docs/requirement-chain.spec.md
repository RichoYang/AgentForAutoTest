# 跨系统需求测试链路

本轮基线为 AgentOS 1.64.2，main / 7dcfb338e102982f38215f6f4bc2cd350e9e85a4，开始时工作区干净。只修改系统代码与受控验证，不部署、不接续取消任务、不执行真实业务或发送群测试消息。

## 调用链和差距

入口 requirement-testing → requirement-test → executeCases → requirement-agent / requirement-adapter → requirement-agent-resources；结果进入 requirement-report 和 ReportDelivery。

| 分类 | 当前事实及增量 |
| --- | --- |

| 外部 | 当前聊天提供 in-app browser，但后台无宿主桥接；OA 人工操作、正式重复事件入口、部署产物、真实账务和飞书应用联调需独立实证 |

## 不变量

- 交接绑定任务、用例、尝试、执行版本、资源身份和不可复用挑战。仅配置的可信执行端签名及文件摘要校验通过才接收；签名证明来源，不替代业务断言。未配置执行端时输出待办并等待。
- 操作发送前保存意图；丢回执先回读。保存结果之前中断不能推出未执行。取消终态不能自动接续。
- 共享样本保留关联用例、初态、账务快照、节点和清理责任；需要后续用例或日期时不能被逐例清理。独立样本故障不影响其他样本。
- 产品确认、开发声明、测试观察分开；开发修复只触发复测。执行版本和旧结果不可覆盖。
- Mock/受控替身证据和真实 UAT 分开。HTTP 成功不等于业务状态或流水成功。
- 投递逐件持久化、幂等发送、以应用身份核对原话题和附件字节。message_id 仅为发送回执。

## 验证策略

先验证入口合同，再验证实现。重点覆盖中断窗口、并发、跨例跨日保留、版本变化、缺修复、投递部分失败与读回不一致、凭据及证据来源。TPM 15.1 金额及状态只放样例配置。真实业务和宿主未联调不标完成。
