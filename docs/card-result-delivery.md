# 结果卡展示与投递恢复（1.59.1）

任务执行、完整答案保存、卡片更新和完成提醒是独立状态。模型已结束不代表飞书已收到结果；排查时对照 job.status/result 与 cardMessages 的 revision/deliveredRevision、failures、retryAt，不因卡片旧画面重复业务查询。

`fitResultCard` 在字节检查之前统一调用 `fitNativeCardTables`，按当前 IM 消息卡路径保留一个原生 table，额外 table 转成带列名的逐行文字。顺序、零值、空值表示和正文语义保持；嵌套表格共用消息预算。平台额度来自本实例同一路径真实拒绝/接受结果，并非宣称所有飞书内容产品都只支持一个表。

额外文字使主卡超过28000字节时，展示收缩且注明完整结果入口，完整 canonical result 和详情分页不缩减；不通过只保留前几张表丢掉答案。详情分页使用既有字段文字和按钮阅读。表格或文件请求仍保留原输出意图，不因为卡片限制取消附件交付。无新增配置、依赖或用户授权步骤。

`LiveCards.deliver` 对持久化的未投递卡重新适配，事务中核对 revision/generation，仅改变原 outbox 的布局和交付版本。原机器人/profile/目的地/任务状态/完整详情不变，重启后也可继续。不新建卡、不重放模型或查询；只有原卡实际投递通过，才发送其原有完成提醒。

遇到平台 `11310` 或明确 `card table number over limit`，同一版本保存不含原生 table 的文字回退，下一次投递使用新布局。已经是文字时不反复改版本；一般网络失败仍按已有退避重试。deliveryRepair只记录脱敏类别和时间，不保存原始CLI错误、凭据或正文到额外公共诊断。

验收：模拟两系统并发旧 outbox；平台明确拒绝后的下一轮同卡投递与完成提醒；一般网络失败；超长转换后的字节容量和完整分页。真实部署另外核对同messageId、revision=deliveredRevision、failures=0及原任务结果保持。完整私有跨机、Windows和不同平台消息路由需要单独验证。

迁移沿原有程序包、完整runtime/data（含cardMessages/details）及私有配置；代码包包含本说明、转换模块与回归。回退先待任务和投递空闲、备份最新状态；已转换的文字卡兼容旧版，但旧版会再次产生多表拒绝，不建议恢复旧无效outbox。不得回灌旧业务任务状态。
