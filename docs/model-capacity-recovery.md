# 模型容量等待与恢复（1.58.7）

只对明确 MODEL_CAPACITY/Selected model is at capacity 的只读分析暂停提供自动恢复；超时、认证、权限、业务错误不归入该类，实施/业务写入不会盲目重放。默认模型配置不变。

环境规划是仅返回受控工具选择的模型会话。容量失败时把已完成结果、步骤、未修正输入及取证说明保存为当前job/环境scope下的model_checkpoint完整工具结果，返回不含业务凭据的opaque resultRef。反复容量失败但没有新的业务执行或新证据时复用原检查点引用，不按轮次复制整套数据。退出原执行器并关闭数据库连接，任务持久化为awaiting_clarification，但卡片显示“模型繁忙·等待自动恢复”，不索要补充或重问。5/10/20/40/60秒退避，之后最多间隔60秒尝试，没有总尝试次数或整任务截止；等待不占用执行器。

控制面重启后仍从保存的nextAttemptAt恢复。排队前逐项核对原任务状态、系统/身份/环境/模板/配置摘要，按原只读范围续期；并发调度只允许同一waiting状态转换一次。取消任务不恢复；配置改变或恢复会话不可核验时保留现场并显示复核要求，不扩大权限。

环境恢复新建纯规划会话并加载完整检查点（不是重放旧工具调用）；仅重查连接/只读事务及已有数据集目录。旧临时setRef不保证有效，需从保存来源重建，结构缓存可定向重新读取。历史结果与新连接不冒充同一事务。已执行的业务查询、文件生成和投递不自动重放。

源码只读会话仍先沿原线程做已有的一次临时恢复，若再次明确容量失败则保存原threadId/固定workspace/questionId等待，恢复必须能核验同一会话与固定源码，不默默新建未知会话。缺少有效会话则停在复核状态。真实其它错误仍保留原分类与环节；结果摘要失败不能覆写最初故障。

成功继续后清除当前等待状态；用户可在原卡取消或刷新。需要迁移完整runtime/data，特别是tool-results/model_checkpoint及依赖的datasets/完整rows文件、源码取证和模型会话。跨Mac的原本机模型会话可能无法恢复，不能仅复制opaque引用宣称可用；本轮未验证完整跨机及其它OS路径。

合成回归覆盖多次容量失败、完整结果保存/进程重建、已完成查询仅执行一次、过期范围续期、并发、不同项目、权限变化、取消、源码线程绑定和卡片状态；真实原卡接续结果另行验收。

若检查点保存失败，明确保留MODEL_CAPACITY原始分类及MODEL_CHECKPOINT_SAVE_FAILED/存储错误码，不假装已进入可恢复等待，也不丢掉已有成果后要求用户重问。范围校验和真正排队之间若任务身份、检查点或授权发生变化，本轮不覆盖新状态。源码执行前再次核对保存的Harness指纹，角色规则变化须维护复核。

环境恢复会重新签发原范围的待领取票据，旧 startedAt 保存在恢复审计中；新租约只能领取一次。测试必须覆盖等待→调度→新租约→实际环境领取，不能只验证排队。
