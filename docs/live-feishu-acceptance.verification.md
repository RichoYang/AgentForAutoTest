# 真实飞书群隔离验收

2026-11-09 在已部署的 TPM 专员上执行。程序版本、入口消息、报告和部署分别记录。模型沿用实例的 `gpt-5.6-sol/high`，真实群中的需求均为本轮虚构材料。正式仓只登记脱敏结论，消息、文档、附件及完整时序留在私有证据目录 `.local/live-feishu-acceptance-20261109`。

## 隔离与入口

1.52.0 的同一机器人 profile 只能绑定一个需求项目，且群路由必须与该项目相同。现有群无法选择一个话题使用独立资源。新增回归先复现拒绝，再为同一既有消费者增加精确的群、根消息、需求链接绑定。默认群项目及权限保持原样。子项目继承既有身份边界，Runner 启动模型前核对项目摘要、资源配置摘要和源码根。

隔离归档和审批各使用独立 Git 根、回环 HTTP 服务、专用 MySQL schema 与限制到本库的账号、独立浏览器上下文及报告路径。实际验证跨库查询拒绝、未登记资源写入拒绝、不同话题或文档不能进入隔离路由。需求读取、用例发布、消息回读和文件下载使用同一已授权飞书文档身份，群消息仍由原专员消费。

## 真实控制和投递

- 1.52.0 收到新话题的只读进度探针，回复该话题没有任务。1.53.0 由原消费者收到带指定需求链接的真实消息，绑定实际事件 ID、消息 ID、话题和隔离项目。没有另起飞书消费者。
- 取消对照在隔离服务实际创建一条数据后从原话题取消。已确认旧进程退出，取消后新增场景写入为零。原话题发送「恢复清理」后，同一个 Job 只执行对账、删除及回查。4 条用例保留未执行，台账 1 条变更、1 条已核验清理，库内零残留。
- 取消报告经原话题投递。下载文件与本机已登记产物逐字节相等，25,772 字节，SHA-256 `6cb358b4e21560e7d8899f63747cdff26d3501781854376c9adcfd293ac10a9e`。读回 15 表、15 份预览及视觉检查回执，独立打开下载文件验证用例状态、变更和清理统计。用例表逐单元格与发布摘要一致。
- 归档正例在取消任务清理完成后独立接单。两条实际飞书消息 ID 不同，专员返回同一 Job，状态库只有一单。平台未观察到同一事件 ID 重投；用真实回读与接单所存事件 ID 重建归一事件，在私有数据目录经正式入口重放两次，仍只有一单。该补充验证无实时消费者、无 Runner、无业务副作用。
