# 可用业务证据与补充来源接续（1.59.2）

适用于多来源只读调查：已有数据库结果，继续查看报表或其它补充网页时遇到真正的登录或访问缺口。网页故障不应覆盖已核实成果，也不应自动把该平台变成业务问题的唯一完成路径。

入口为新建 continuousInvestigation 且 taskIntent=analysis 的任务；Store记录内部策略 availableSourceReviewPolicy=preserve-and-review-v1，无需新增私有环境配置。历史等待任务不自动批量开启，恢复须遵守实例维护流程，保留发起人、群、profile、项目、环境、固定源码和数据集。该策略不授予任何新环境、数据源或写权限。

`availableEnvironmentEvidence` 只选原任务已持久化的 ready/partial 环境结果，需有有效readAt、完整结果摘要哈希、实际业务查询与非零结果行，失败和仅schema不算。`preserveAvailableEvidence` 在登录等待前列出这些成果，保留原时间及新的具体缺口，不能冒充当前网页已读。

控制面已有网页登录检测优先恢复会话和本机凭据。明确缺凭据、拒绝、改密、请求范围受阻、服务或请求错误时，若已有上述业务证据，`deferUnavailableWebsite` 事务核对当前等待状态、scopeHash与最新环境配置、项目及分级，保存原计划/等待结果，添加独立environment_unavailable资料，再清除活动网页授权与跨阶段检查点，回到同一任务源码审阅。不可用资料没有environmentEvidence，不计为成功查询。后续数据库/网页申请仍重新规划，不能复用旧授权为新来源放行。

加载中、普通自动重登、验证码、限流不因此改变现有恢复方式；没有业务证据或非连续分析任务也保持原等待。相同环境/配置/原因已延后过时不反复自动排队；任务、查询和耗时无新截止，新增真实登录条件或配置变化仍可按原流程申请。用户取消或作用域变化不能被后台接续覆盖。

源码模型应回到原始业务目标，先回答已核实部分，定位可用来源后补足指标并生成/验证文件。不同来源的销售额、净额、退货、利润等不得混称；字段无法核实单列缺项，不补零。用户明确指定某平台的原始报告，替代来源不能当成取得原报告；若只有该来源能完成，仍精确说明配合动作。不能为了卡片变绿降低原要求。

迁移带新增模块、测试、文档及完整runtime/data（含失败记录、数据集、原始取数时间）。回退前等待空闲、备份最新状态；queued源码审阅不得交给不理解其接续资料的旧版，需逐项处理；不回灌旧任务状态。macOS本实例真实接续、模型自主选择新来源、完整私有跨机与其它OS分别记录，不能用单测代替业务验收。
