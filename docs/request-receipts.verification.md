# 请求参数、审计与外部回收衔接验证

## 版本和边界

实现版本为 AgentOS 1.59.0，接续 1.58.0。运行源码共 144 份，冻结 SHA-256 为 `1cba80c45cc2040bd0055d5a2b3763a7db49101b4d9fccf2e57027d46bd25baf`。冻结摘要按路径排序后的 `{path,sha256}` 数组 JSON 计算。业务源码版本继续使用每次实际读取的来源和文件摘要。

本轮仅使用专属隔离资源验证业务动作。真实 LTX SIT 的配置调查和隔离测试分别留证。原取消任务和既有 LTX 报告保持原样。部署目标仅 LTX。

## 实现与使用

漏项夹具原先在省略 mode 时返回完整窗口，真实模型实际使用了这一分支，保留其通过结果。最终夹具严格区分只返回能力的 capability 与实际收集的 collect，再使用相同业务要求复验漏项。

参数记录按已登记 `queryEvidence` 字段白名单采集。多值顺序保留，缺失表示为空数组，空字符串表示 `[""]`。wire 参数为解码后的字符串数组，原始工具输入另记 `queryInput`，null、数值 0 和文本 "0" 保留区别。超出安全整数范围使用精确文本，禁止不安全整数输入。经过脱敏变换的字段从可比较参数中排除，并计入未记录参数。既有未选择参数证明的操作保持原序列化行为。

`requestCorrelation:true` 仅用于已核实接受该请求头的操作。连接器发送 `x-agentos-request-id`，外部审计须从实际受控来源回读该值。`requestProof.audit.matchRunner:true` 先按冻结合同确定业务范围，再检查每个本地请求 ID 唯一匹配、方法、路径、已选参数和未记录参数数量。带请求 ID 的独立取证请求仍计入完整 Runner 调用记录。未知或缺失证据继续拒绝。基础路径测试仍可独立使用。

浏览器对已登记的精确 HTTP 读入口采集相同字段，页面网络响应保留关联 ID。唯一匹配的登记合同可以启用服务端请求头关联。数据库台账目前证明连接资源、阶段和传输，SQL 快照仍由原合同与快照证据证明。数据库连接记录无法单独证明 SQL 参数或某行归属。

取证预检携带主机实际使用的 collectionPolicy，明确能力探测的同一时点窗口、prepare/scenario 的正式起止绑定、相关键、来源与完整性响应规则。预检核验取证能力，正式窗口内容在动作后收集。

外部回收能力预检只核验渠道和合同。实际回收必须在声明时点之后取得。回执核对受控来源、责任人、对象、Job、用例、尝试、测量轮次和唯一回执 ID。Runner 自身恢复和外部所有者回收分别记录。

结束后核验由原请求者在原话题 @原专员发送“核验外部回收”。入口只接受已完成且已验证原报告与自身清理的 Job，仅读取原登记的 GET 来源。资源身份、源码证明和配置身份变化时拒绝新取证。记录使用私有文件原子追加，关联原报告 ID 与 SHA-256。同一合同与来源覆盖多个过程检查时，保存一份回执并列出全部检查号。重复命令回读既有记录。原 Job 状态、台账和工作簿保持原字节。

## 真实 SIT 条件

| 资源 | 现有材料证明 | 解除条件 |
| --- | --- | --- |
| Web 平台 | INI 含入口和角色配置。可信本地认证源码存在解码后记录完整登录参数的路径 | 将实际构建与有效日志脱敏证据绑定，再核验当前登录身份和角色字段 |
| 主库 | INI 含连接配置。库名未指定，既有元数据有服务器级授权 | 受控绑定提供明确库表范围和满足该范围的只读主体 |
| 库存库 | 存在项目资源声明 | 补齐有效连接主机、端口和认证组合 |
| MongoDB、原生移动端 | 存在资源声明 | 对应正式连接器另行验收 |
