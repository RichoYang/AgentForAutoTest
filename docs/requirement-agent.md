# 工具型需求测试专员

## 配置和入口

在项目的 `requirementTest.execution` 中设置 `mode: "agent"`，重启对应实例。沿用项目 `repoPath`、非生产 `environment` 资源、SIT/UAT 别名、凭据来源及操作权限。无需为每个需求手工补齐接口目录。

```json
{
  "mode": "agent",
  "knowledgeFile": "<实例数据绝对目录>/knowledge/project-test-operations.json",
  "login": {
    "resource": "platform",
    "path": "/your-login-endpoint",
    "accountSelector": "input[name=account]",
    "passwordSelector": "input[type=password]",
    "submitSelector": "button[type=submit]",
    "tokenField": ["data", "token"],
    "identityFields": { "userId": ["data", "userId"] },
    "header": "Authorization"
  }
}
```

不需要登录的隔离站点可省略 `login`。选择器、字段及鉴权头必须按项目核实，上例不是通用登录协议。另一资源使用表单登录时，可配置 `resourceAuth.<资源名> = {"kind":"form","path":"/login","fields":{"username":"username","password":"password"}}`；值引用该资源的本机凭据字段。凭据仅由连接器读取，模型接收脱敏资源目录。

`login.identityFields` 可按真实登录响应配置公开身份字段，不能指向令牌或密码。连接器将实际身份及脱敏回执交给变更审查器，核对“修改当前用户”等隐式目标与前置快照；身份随变更意图保存，执行及恢复时重新核对当前会话，换账号不能恢复到另一个用户。此身份依据不替代操作源码和唯一对象核验。

项目已授权恢复式使用既有测试对象时，可在对应 `environment.resources.<资源名>` 设置 `reversibleSharedWrites: true`，并保持 `scope: "full_crud"`。这允许任务调查后使用既有对象，不要求逐接口名单；每次仍须回读唯一 ID、保存前置快照、证明写入和恢复目标一致。新建对象继续使用任务前缀。未配置时只允许专属测试数据或原有 `sharedTargets` 明确列出的目标。页面导航触发的辅助写入可登记为 `kind:"browser", action:"goto", path:"/页面", effect:{path:"/实际写接口",method:"POST"}`，同样通过 mutate 记录和清理，不能标成只读查询。

群聊入口、需求/用例路径、原话题控制及发布策略沿用[需求测试工作流](requirement-testing.md)。原请求者在原话题回复「重试未执行」，会在同一 Job 保存旧尝试并重新处理未执行用例；回复「重试失败」会同时重跑失败及未执行项，并继续尚无结果的用例。已通过结果、原用例索引和发布回执保持。仅在任务暂停、等待或结束后接受重试，未决变更必须先通过「恢复清理」对账恢复，不能删除台账绕过。

源码搜索和文件枚举包含根 Git 忽略规则列出的业务子仓；凭据文件、Git 内部文件及依赖目录仍排除。数据库不变性断言会保留实际查询口径，基线与当前查询不同时由独立模型审查字段映射、过滤及聚合是否可比；口径错误返回可恢复工具错误，不生成产品失败。真实数据错误仍保留失败，后来通过不能覆盖旧断言。

`test_plan` 的 `action: "inspect"` 可回读冻结计划和断言；`identityCorrections: [{checkId,subject}]` 只修正尚未比较检查的主体绑定。原预期、依据及渠道不可改，拒绝时记录具体冻结字段路径。完成数据准备并回读后再冻结场景基线，原始快照继续用于清理恢复。

原文要求在某次写入前核验实际状态时，检查可登记 `beforeAction: {operation, input?}`。`operation` 是已登记的写入名称。`input` 是区分动作的实际入参子集，适用于同一操作涉及不同对象或阶段。Runner 要求从冻结后、准备完成后的独立只读观测完成该检查，随后才接受匹配的场景动作。测量方法样本、准备回执和恢复快照有各自用途。动作边界记录已用的原始观测，后测不得替换它。未来结果仍在动作后取证。若原始前态丢失，按现有 `test_measure` 恢复后重测规则处理。

`test_assert` 在比较前审核字段是否真正代表待测指标，可用 `sourceRefs` 引用已读取的DTO、业务实现或页面代码补证。元素数量、已使用金额、状态码不能替代待测余额。相同检查与测量契约可复用审核，错误绑定只记工具错误，修正后重新比较；真实错误值仍保留失败。

登记操作产生的观测携带该次已复核的源码、资源、Schema 和身份边界。断言默认使用本次操作的源码证据，可显式补充测量相关来源。历史源码引用仍按当前文件校验，边界变化时重新读取并登记。对于多个检查误用同一个冻结前观测，诊断按原观测汇总，分别记录每个检查的尝试及其后续有效比较。新增其他观测不会关闭该缺口。

实际差额用 `calculation: {terms: [{field: ["body","allocated"],sign: 1},{field: ["body","applied"],sign: -1}]}` 替代单个 `field`，程序保留操作数与精确十进制计算，独立预期不变。页面要求“显示剩余”时，计算不能冒充展示。页面观测含 `measurements` 和DOM；经核实的缺失字段记为 `observed: null, missing: true`，不会把没有匹配元素记成0元。

MySQL 查询与变更参数统一保留精确十进制文本，避免旧版服务对混合数值参数重新预处理而损坏大整数条件。大整数ID须从回读字符串沿用，不能先转为 JavaScript 数字；已舍入的输入会被拒绝。连接器不使用查询属性协议。影响行数不符会返回实际/预期行数并回滚，仍需对账原意图，再决定恢复或重试。

需求需要数据库时，先从已授权资源使用 `test_schema` 发现库，再用项目源码和目标环境数据源确定使用哪一个。默认库可以为空，同一资源支持多库分别连接。用 `test_connection` 复核目标库，用实际库表字段和同一个业务键关联跨库证据。详细配置和环境边界见[受控 INI 接入](controlled-ini.md)。

已发布用例续跑时，正文、顺序、表头和附页仍逐项核验。原表的“测试结果、备注说明、测试截图”列可保留其他执行者的批注；程序保存带来源的批注快照，不覆盖这些单元格，也不将其导入专员本轮结果。正文冲突会记录具体单元格并暂停。

## 实际执行链路

Runner 复用 Codex app-server，通过任务专属动态工具读取本项目源码（含子仓引用和历史）、调查数据库 schema、登记经源码审查的操作、准备数据、执行场景并取证。普通群聊进程仍拒绝工具审批。HTTP 保留完整脱敏业务响应，浏览器保存真实 DOM 观测和截图。消息与调度使用已绑定资源的 HTTP 管理入口；SQL 查询在只读事务中执行，数据库变更使用明确表/列、完整唯一索引条件和预期影响行数。

没有任意终端脚本入口。不兼容的登录或业务协议需要补相应连接器，不能把未支持的动作报告为已执行。源码审查由模型判断语义；资源归属、写入权限、台账、主体一致性、断言计算和回读由程序校验。模型审查本身不等同于操作系统隔离或对未知业务副作用的证明。

每次写入先登记意图、唯一归属、真实前置快照和恢复契约。实际变更、验证和恢复必须指向同一业务对象。回执丢失后先按保存的验证操作对账，不能盲目提交。`verify.stateFields` 可选择参与恢复比较的稳定业务字段，排除响应时间戳；完整原始快照仍保留。多对象、多期间和独立基线保存在 Job 的别名与观测记录中。

计划候选、字段错误及修正全部留档。看见失败后不能修改期望、渠道和原需求；尚未取得可比结果的身份绑定可经再次审查纠正，旧计划保留。页面断言及主体绑定只接受实际 DOM `values` 字段，同时要求截图和业务就绪条件；浏览器捕获的网络响应不能冒充页面取值。主体只包含实际能回读的对象与期间，前后时点和切换序号写入步骤。浏览器可以对已登记的只读请求模拟延迟或错误，证据标注模拟，清除规则或关闭独立浏览器后解除。并发操作分别记账并回读。

模型的清理工具与 Runner 使用同一台账。每条用例结束先恢复并回查，再执行下一条；异常或恢复先核实遗留副作用。清理失败保留资源锁与尝试记录。旧执行器升级仅在原锁身份匹配且不存在未决变更时迁移；否则应先恢复原绑定处理清理。执行器或前置证据不足记未执行，实际资源拒绝/不可用证据对应外部阻断，产品错误单列失败。

`processChecks.kind: "report"` 对应固定 15 表报告的生成和验证，由报告阶段登记实际产物、摘要及视觉检查回执。报告交付属于后续阶段。若执行阶段的 `cleanup` 过程检查未证实，Runner 可以在同次尝试和测量轮次的恢复后追加复核。审查使用实际台账及晚于恢复动作的原始回查。旧业务结果与旧过程覆盖保留，结论另存 `journal.processFinalization`。旧计划中未标明阶段的过程要求保持原状态。报告中的执行说明记录构建时证据，登记回执和最终回复呈现产物核验后的状态。

项目 `knowledgeFile` 保存经过审查的操作线索与源码位置。下一任务仍须重查源码和登记，不能把历史对象或余额当作当前事实。通用代码不包含项目需求编号、金额或业务接口。

计划审核使用与工具相同的参数 Schema。内部 `baselines`、`measurementSamples`、已登记操作和覆盖矩阵由 Runner 派生。未冻结的候选可用 `test_plan action:inspect` 查看，再用 `action:repair` 的 `replace` 替换受影响的步骤、检查或阶段段落。冻结后的身份修正和恢复重测规则照常适用。

原预期要求在动作前保留完整的准备后范围时，用 `processChecks[].beforeAction` 指定登记写入及匹配入参，并用 `baselineChannel` 声明证据渠道。冻结后回读准备完成的范围并执行 `test_process`，写入前会核验过程回执。证明完整性时应按原范围使用可核对的快照或实际原始结果。业务前态预期仍用独立业务检查。过程前态不计入业务断言。

`pageStages[].ready` 使用浏览器就绪条件的同一结构。到达该阶段后实际等待并观测，阶段回执必须保存匹配条件和真实页面动作。浏览器 `observe.record` 可以原子提取可见 DOM 行或可配对的平行列，并按完整键选出唯一记录。并列节点须有源码同序依据，JSON 列须能无歧义解码。普通分隔符拼接不会被猜拆。断言引用 `["values",记录名,字段]`，对应身份须从同一 DOM 记录核验。只有独立完整范围足以证实单目标时，才用普通可见字段证明单记录。

目标行只会在动作后出现时，`measurement.sampleSubject` 可用同阶段、同范围的另一条真实 DOM 记录预检读取方法。预检仍需真实等待、截图和精确键，报告保留样本身份。场景断言核验冻结的目标身份，沿用同一记录布局、选择器和字段。该样本不能用于动作前基线。

原文要求仅允许特定调用时，用 `runnerScope.phase` 和 `allowed` 声明阶段及完整路由白名单，路由包含 resource、transport、method 和 path。数据库连接记录为 `database CONNECT /`。执行器核对该尝试所有测量轮次的实际调用，包含冻结前和重建测量前的请求。冻结后拦截范围外请求，必要恢复仍按原授权执行并保留证据。指定路径的次数证明继续使用 `requestProof`。

请求的查询参数需要关联对象或视图时，为只读 HTTP 入口登记 `queryEvidence`，列出可记录的业务参数名。冻结约束中的 `query` 按参数名指定解码后的值数组。同名多值保留线上的顺序，空数组表示该参数未发送，`[""]` 表示发送了空字符串。`queryInput` 可进一步核对直接 HTTP 的原始 JSON 类型。大整数使用十进制字符串。只在已声明的业务字段上把输入数组发送为重复参数。使用 `exactQuery` 时必须能解释所有实际参数。缺少观测或受保护的字段无法证明该限制。

直接 HTTP 的实际响应通过请求 ID 对应观测。浏览器只对精确匹配已登记路由的网络请求取已授权参数，XHR 或 fetch 记录随页面观测保存。数据库连接、浏览器导航或未登记参数的请求仍可证明各自的路径范围。需要逐条与独立审计对账时，先从源码核实服务接收并保存 `x-agentos-request-id`，再对对应入口启用 `requestCorrelation`。审计合同设置 `matchRunner`，核对请求 ID、路径、参数与完整时间窗。调用者填入业务键或返回相近时间均不足以关联。

外部准备者回收登记为 `external_cleanup`，记录负责主体、关联对象及业务比较后或 Job 结束后的边界。配置已登记的只读回执操作时，先用 `process_preflight` 核验取证能力。真实回执可用后核验来源、主体、对象及实际时点。应在 Job 结束后取得的回执单列为待办，业务比较和报告可先完成。工作簿和消息卡显示外部过程的独立状态。

回执入口使用 Runner 提供的 `mode`、`correlation`、`after`、`jobId`、`caseId`、`attempt` 和 `epoch`。能力预检回显绑定并返回 `available: true`。实际回执另需 `receiptId`、`completedAt` 和 `verified: true`。业务检查后取得的回执随本轮报告留档。对于 Job 结束后产生的回执，由原发起人在原话题 @ 专员并发送「核验外部回收」。专员从原登记入口读取并核验，原报告的 ID 和摘要随追加证据留档。同一任务、尝试、轮次和报告下的相同来源及合同共用一份回执，关联全部检查号。重复核验回读既有记录，历史报告仍呈现生成时的结论。

项目接入时可在授权源码目录登记实际启动配置、连接器版本和响应构造入口，省去人工解释有效参数。数据库列类型与只读 SQL 能证明存储和数据库连接器的值。HTTP 字段的 JSON 类型还需读取有效的应用连接配置与序列化实现，或核对相同业务范围的实际只读响应。运行对象、金额和状态每次重新取值。

同一 Job 可复用已审核且契约未变的操作。重试提供上次计划、别名和观测索引，`test_evidence` 可回读旧记录并明确标记历史；新尝试的别名、基线和断言必须引用重新取得的观测。直接数据库核对和准备操作的审查同时使用已回读的表结构及业务规则，不要求产品预先存在相同的临时 SQL 接口。

## 验证和排查

`GET /health` 项目项应显示 `executionMode: agent`、`executionProtocol: native-tools-ledger-v1`，发布策略保持 `case-scoped`。健康只证明配置路由；实际验收必须核对原飞书消息、Job 工具调用、业务断言、清理和报告投递回执。

`data/requirement-tests/<JOB>/agent-tool-state.json` 保存操作、源码摘要、别名、观测、计划及尝试。原 `journal.json` 保存业务意图、对账、清理和历史尝试。工作目录的 `diagnostics` 保存脱敏的计划候选、审查及模型事件，结束时归档为报告目录内的逐用例 `.jsonl.gz` 审计包。业务观测、断言、清理证据和页面截图分别保存在报告目录。排查先看字段错误和真实 HTTP/数据库结果，不手改台账或删除资源锁。

报告仍先运行原 Skill 版本化构建器，再只适配表体行高并重新渲染，固定 15 表、内容与公式保持。视觉检查、重开计数与摘要均针对最终文件。清理或报告未核验时不能交付为完成。

本机隔离验收：配置 `AGENTOS_REQUIREMENT_SKILLS_ROOT`、本机 Codex 配置及需要的 `AGENTOS_REQUIREMENT_POWERSHELL`，运行 `node scripts/verify-requirement-agent.mjs <独立输出目录>`。`AGENTOS_ACCEPTANCE_MODE` 支持 `positive`、`wrong-page`、`multi-object`、`lost-receipt`、`cleanup-retry`、`retry-native`、`navigation-state`、`authenticated-navigation`。真实模型、浏览器、HTTP 和正常 Runner 实际运行，飞书传输与来源是隔离输入；这些结果不能替代项目环境验收。Windows 与其他平台的部署验证需分别记录。

## 数据库观测和全程调用范围

普通只读或指定对象的需求约束业务查询和操作权限。只有源需求明确要求覆盖所有调用时，才为对应阶段登记封闭的 `runnerScope`。涉及其他调用者或独立服务证明时，沿用独立审计入口及能力预检。

MySQL 的 `test_connection` 可设置 `identityOnly: true`，保存当前库和主体匹配结果。连接观测中的 `databaseEvidence` 记录同一连接的 `DATABASE()` 表达式、取值路径、时点和选库方式。固定绑定要以未传入数据库参数的连接回读为据。常规连接检查还读取授权。无默认库时当前库可为 `null`。`test_schema` 保存实际连接身份与表结构，其中 `primaryKey.columns` 是按索引顺序回读的完整主键列。使用 `type: "list"` 和 `operator: "equals"` 比较整个数组。`data.count` 是 SQL 实际返回行数，外层 `total` 只用于分页显示。

全程范围中的 MySQL 路由使用 `transport: "database"`、`method: "CONNECT"`、`path: "/"`，并以 `databaseCall` 声明允许的调用类别和实际连接库。表结构范围可限定表名。自定义读查询需要指定审核过的操作名及规范化的参数值。连接器在派发前检查冻结范围，并将实际命令回执挂到同一连接和保存观测。过程审查以同一份台账核对逐次回执、跨阶段边界和已关联观测，即使该检查没有另行声明白名单。旧连接回执仅能证明连接。表结构观测可以在冻结后独立重读。

参数化 SQL 的 `spec.tables` 分别声明实际 SQL 来源 `role: "query"` 和业务验证对象 `role: "subject"`。先读取各项真实结构。通过固定业务库连接读取 `INFORMATION_SCHEMA` 的列定义时，可在 `test_schema` 传入 `connectionDatabase`。声明用于结构证据关联，查询参数及业务范围仍按实际证据独立审查。
