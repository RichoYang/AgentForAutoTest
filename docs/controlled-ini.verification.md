原版根因用 1.55.0 归档和同一隔离配置直接复现，证据为 `baseline-repro.json`。轮换后原版继续向连接器交付旧凭据且指纹未改变。新版在回调前拒绝，重新加载后指纹改变。该复现未访问网络。

真实 SIT 回执为 `sit-readonly.json`、`sit-mysql-final.json` 及最终源码的 `sit-management-final.json`、`sit-rabbitmq-scope.json`，分别归属相应探针源码版本。探针只请求绑定入口、身份及必要元数据。MySQL 的首次回执将驱动返回的字符串形式 `SELECT 1` 误判为失败。修正探针后仅重跑两个 MySQL 元数据核验。两账号全局授权说明账号的潜在范围，不能代替本次任务的只读授权。没有发现明确业务库时保留 Schema 待核验。RabbitMQ 只对绑定 vhost 与当前主体查询单条授权记录，未枚举其他账号、vhost 或队列。[RabbitMQ HTTP API](https://www.rabbitmq.com/docs/http-api-reference#get-apipermissionsvhostuser)

XXLJob 取证使用真实同源页面和脚本确认登录路径及字段，再由执行层提交一次既有配置的登录。原始探针只以 302 判定认证后重定向，保留其实际 303。二次审阅按上游已认证分支和 Spring 重定向语义确认会话，未重试登录。证据为 `sit-xxl-entry-contract.json`、`sit-xxl-login.json`、`sit-xxl-session-review.json`。[XXLJob 认证控制器](https://github.com/xuxueli/xxl-job/blob/2.4.1/xxl-job-admin/src/main/java/com/xxl/job/admin/controller/IndexController.java#L52-L67)、[Spring RedirectView](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/web/servlet/view/RedirectView.html#setHttp10Compatible(boolean))

LTX 本地认证组件 `db29f46e` 的 `AuthController.login` 在解码后拼接登录参数输出 INFO，而 `LoginParam` 用 `@Data` 并含 password 字段。本轮已有一次授权的会话验证，发现该源码风险后未追加登录。SIT 运行构建、日志级别及日志内容未读取。由认证服务维护者先核对实际构建和入参脱敏，再补实际角色核验。

## 待决策略

- 全局 PRD 要求确认，ESB 的生产查询节声明免确认。需明确全局规则是否有意为该资源设例外，以及例外的审批与身份。需求 Runner 仍只允许 SIT/UAT。
- OLtx 生产 MySQL 声明 `allowed/full_crud`，与全局生产确认及其他生产只读声明存在差异。需确认资源独立授权、库名和最小权限，任何生产操作另行明确授权。OLtx SIT 网页本身也声明需明确确认。
- 全局数据库说明与部分字段对变更的表述不同。Runner 使用已知可执行字段的权限交集。若未来需要真实数据库变更，先确认逐对象授权及最小账号能力。
- 绑定节改变、凭据轮换或撤权时，当前句柄失效。新任务读取当前项目绑定。修改已运行实例的项目配置仍须遵守该实例的配置加载流程。
