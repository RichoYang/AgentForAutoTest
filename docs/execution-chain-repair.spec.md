历史诊断明确包含合理拒绝：未限定租户、两个摘要算法长度上限不同、空集合返回形态不同。不能放宽这些审查。某小集合原始行数及长度能支持未截断判断，但仍需核验完整字段和主体范围；不改历史结果。

| 历史首条检查的诊断性质 | 实际只读证据与处理 |
| --- | --- |
| 合理拒绝 | 两层 GROUP_CONCAT 可能分别截断；仅在后测添加 WHERE 或 CASE 完整性条件会使缺行/NULL 与旧基线口径不同。保留拒绝，不改历史预期或结果。 |
| 上下文缺失 | 旧 SQL 已返回 chunk 长度、记录数及 digest_complete 等字段，但审查只收到选中的 full_hash，不能从字段名称推断实际完整。辅助证据传递原始字段值及核验约束，必须来自当时已保存观测。 |
| 工具表达能力不足 | 每次临时编写摘要 SQL，完整性校验与数值断言分离，不能统一解释空集、分页及变更字段。新增全记录快照，由程序采集、校验和比较；仍要求明确真实租户及对象范围。 |
| 恢复流程缺口 | 模型把测量修正和冻结预期替换混在一起；已有基线不能证明完整时缺少明确的恢复重测入口。增加先实际恢复回查、保存旧历史、再新时期重测；不接受事后查询充当前基线。 |
