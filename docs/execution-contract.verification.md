# 执行契约与页面取证验证

AgentOS 1.58.0 基于 1.57.0 继续使用原测量、变更台账和 15 表报告契约。验证分别记录确定性回归、真实组件、正常 Runner 和群入口。具体项目的话题 ID、夹具地址、实例配置和运行记录保存在部署方私有证据目录。

| 证据类别 | 修改前 | 回归判据 |
| --- | --- | --- |
| 计划与审查 | 审查要求填派生的 `baselines`、过程 `measurement` 和阶段 `ready`。相应参数被拒绝。登记的只读入口也可能从审核材料中缺失。 | 审查收到可提交 Schema 和已登记入口。工具明确提示派生字段及合法替代。检查项和准备过程分开表达。可修正尚未冻结的计划片段。非法的过程动作、路由和回执合同在冻结前被拒绝。 |
| 过程基线 | 测量需要说明准备后的完整状态，缺少直接绑定相应写动作的过程契约。候选执行中已证明集合基线，但变更审查只收到单对象回查和独立服务审计预检。 | 真实 HTTP 计数服务在过程证据缺失、来自冻结前或渠道不匹配时保持零场景写入。冻结后、准备后采集独立观测。变更审查收到已证明的具体字段、范围和时点。旧基线不得被事后重查替换。 |
| 页面对象 | 分别拼接的业务键和标题无法证明配对。归档前不可见的目标行无法用实际目标 DOM 验证读取方法。 | 真实 Chromium 读取可见的同一行，按完整键定位。重复标题、相似键、乱序、分隔符、空集合和加载等待纳入回归。重复键和普通聚合串继续拒绝。方法样本不替代场景目标，实际断言仍须采用相同布局、选择器及字段。 |
| 调用范围 | 对有限入口的检查可能只核对列出的写接口。重建测量时旧记录已保留，白名单校验仍可能漏掉旧轮次。 | Runner 实际发送记录覆盖 HTTP、浏览器与数据库连接。阶段范围内逐条检查，包含重建前的请求。未授权调用、未决传输和无法补证的旧日志版本不证明合规。拒绝后续违规发送时，必要恢复不被锁死。 |
| 外部回收 | Runner 的清理、业务比较和准备者的回收相互依赖，可能无法收尾。 | 分别保存业务比较、Runner 恢复、报告及外部回收。回执按责任人、对象、来源和时点核验。Job 结束后才能取得的外部回执保留独立待办。 |

可单独运行 `node --test test/requirement-execution-contract.test.js`。其中浏览器、HTTP 端点和 Runner 传输是真实本机组件。测试中的模型和语义审查是可控夹具，另用冻结源码上的正常 Runner 验证模型能否自主发现和完成。

`runnerScope.phase=all` 覆盖该用例本次尝试的准备、场景和 Runner 恢复，包含该尝试中的全部测量轮次。它不表示其他用例或其他调用者的所有请求。外部回收须有实际来源和证明，工作簿可以保留待办，已投递的工作簿不会因 Job 结束后收到回执而自动改写。
