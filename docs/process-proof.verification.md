## 冻结及真实模型验收

首个会议席位候选在真实 Runner 中取得过独立审计能力回执，后续计划审查仍报告缺预检。根因是确定性门控与计划审查接收的证据不同。最终修复把预检回执传给计划审查，并在准备结束时取得实际窗口，排除之后的确认请求。原席位样本转为回归，另选图书归还作留出。最终 1.55.0 的 142 份运行源码 SHA-256 为 `364ab83451bcebeda607af6ef0c1627ff5502f685106e12958def8eecb98bf81`，实际模型仍为 `gpt-5.6-sol/high`。

图书归还留出 `JOB-process-proof-return-1794209258816` 完成 1 条通过、业务 2/2、过程 2/2。真实模型经正常 Runner 自主生成并回读用例，独立读取同一条码的 `ON_LOAN` 与归还后的 `AVAILABLE`，逆序恢复及回读后零残留。服务收到 15 次 HTTP 请求，其中实际准备、归还、回退、删除各一次。2 次工具拒绝、0 次测量重启。15 表工作簿完成逐表视觉检查和独立文件回读，报告 SHA-256 为 `cddf38cbcf574d551a28b60c127cf9fe340ca1447286bfce280440f6aa287313`。

资料组合准备 `JOB-process-proof-publication-focused-1794209968742` 完成 1 条通过、业务 4/4、过程 3/3。真实 Runner 证明准备窗口内实际发送 `POST /bundle` 一次、`POST /version` 零次。独立 API 核验两个版本及发布前后正文。保留 3 笔变更及验证恢复。服务收到 27 次 HTTP 请求，发布及恢复使用相同入口共 4 次，准备及删除各一次。4 次工具拒绝，0 次测量重启，最终零残留。报告 SHA-256 为 `5b030c1564c805516243304bc63a1cc55864a6e736568b02c987f857b3566993`，15 表逐表视觉检查与独立回读完成。

该真实任务的结束工具曾返回 `P1_PREP_REQUEST_COUNTS (process, prepare, invalidated)`。工具同时列出使证据失效的变更 `1:scenario-restore-first-pointer`、业务 4/4、报告项 `P7_REPORT` 延后和补审工具。模型用保存的请求证据完成补审。复核期间无需重放准备请求。原始 1.54.0 审批产品失败留档，模块回归验证产品失败仍可在满足收尾条件后正常登记。

审计回归的较早设施未明确区分可供查询的范围和返回的实际窗口，模型在一次尝试中又将旧时间写死在操作登记。程序以窗口证据不足拒绝预检，相关业务写入为零。原未执行、报告与诊断按 Job 保留。隔离审计服务的修正仅涉及实际返回窗口与规范时间比较，AgentOS 源码指纹保持不变。
