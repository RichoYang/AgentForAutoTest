# 可使用工具的需求测试执行

## 问题和目标

旧执行器只让无工具模型选择静态操作目录，无法调查源码、解析用例代称或构造缺失前置；已有未执行结果无法重试，计划错误未保存具体字段。新的 `execution.mode=agent` 复用 Runner、资源授权、Codex app-server、变更台账和两个 Skill，在同一 Job 中完成调查、数据准备、执行、断言、清理与报告。通用执行器不包含业务项目的编号、金额、对象或接口。

## 契约

- 项目配置一次绑定源码根、非生产资源及凭据来源；工具只取得当前项目/环境/Job/用例身份，凭据保留于本机连接器。
- 模型可读取源码、发现接口/数据结构、查询真实数据、操作浏览器、运行受控 HTTP/数据库/消息/调度操作。业务写入必须先登记归属、独立回读、前置快照、恢复与恢复核验。
- 导航自动触发的写入与点击提交使用相同台账。已有测试对象可由项目资源一次授权恢复式写入，每次仍验证唯一 ID 与前置状态；不能用该授权创建无归属对象。源码搜索支持目录及单文件，工具错误须有可修正的字段诊断。
- 独立基线、多对象和多期间采用显式别名映射，每项断言关联步骤、主体、期间、渠道及来源。UI 断言不能用 API 替代。页面等待业务就绪而非仅元素存在。
- 计划是有版本的结构；错误保存脱敏输出及字段级诊断并反馈模型修正。不断有进展时没有整个任务的耗时/轮数上限；重复无进展可暂挂并保留证据。
- 旧尝试存档，重试按新 attempt 隔离；未决写入先对账。版本迁移只在原资源身份不变且无未决变更时进行，原发布回执和用例不改。
- 已核验发布表的三列执行批注允许由其他执行者维护，续跑存快照而不覆盖或冒充专员结果；用例正文、顺序、表头和附页变化仍阻断，并记录单元格差异。原发布版本与回执保留。
- 数据库日期/时间保持数据库原文及精度，不能因 JSON 脱敏丢成空对象或改变期间；非数据库 Date 值遵循标准 JSON 表达，历史观测不伪造补值。
- 正常、异常、停止后恢复均从台账清理并回查。清理不明不可完成或盲目重试。
- 发布信息仍按用例前置处理，缺构建号/镜像及 CNB 权限不是全局执行门槛。

## 验证与交付

先复现 UI/API 错配、多主体、异步读取、计划修正、丢回执、清理失败和未执行重试。模块替身结果与真实模型/Runner/工具隔离整链分别记录。部署前检查在途任务和未决变更，备份程序、配置、状态；上线核对源码指纹、飞书原话题入口及原 Job。实际业务由专员执行，原 19 条各自记录通过、失败、阻断、未执行，按原 Skill 固定 15 表交付。
